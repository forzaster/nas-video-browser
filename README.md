# Family Videos — dlnautil for Mac

MiniDLNAなどのMediaServerを選び、動画をクロールしてSQLiteへ保存し、年 → アルバム → 動画で閲覧するPythonアプリ。
動画原本の移動・変更は行いません。MediaServerのHTTP動画URLからプレビューを作ります。

## 起動

Python 3.11以上、uv、FFmpeg/ffprobeが必要です。

```bash
uv sync --locked
uv run uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8765
```

http://127.0.0.1:8765 を開いて「機器を検索」→ MediaServerを選択。
選択時にクロールが始まります。再取得は「再クロール」。SSDPで見つからない機器は「機器URLを指定」から機器説明XMLのURLで登録できます。
MiniDLNAは別途起動してください。本アプリはDLNAサーバー本体を含みません。

1プロセスで動かしてください（複数workersは不可）。開発用reloadを有効にするとクロール・再生キューは中断されます。

## 実装した仕様

- サーバー・レンダラーのSSDP検索と一覧、再検索、機器の保存。
- ContentDirectoryのページング・再帰クロール。音楽・写真のビューは巡回せず、動画の取得元フォルダだけを取得します。
  取得元はクロール開始時に自動判定（ルート直下の「ビデオ／Video」内で、各動画にアルバム情報があれば「全てのビデオ／All Video」、無ければ「フォルダー／Folders」、どちらも無ければビデオ全体、ビデオが見つからなければルート全体）。
  管理者は「再クロール」横のフォルダアイコン（取得元フォルダ）から任意のフォルダを指定、または自動に戻せます。取得元の外になった動画は削除せず非表示（available=0）になり、動画が0本のクロールは失敗扱いで既存の一覧を変更しません。
- MediaServer UDN＋ObjectID（refIDがあればそちら）で識別。
- 同じObjectIDの再取得ではユーザー設定タイトルを維持。元のファイル名やNAS情報は変更しない。
- 年はアルバム名の先頭4桁を優先し、メディアの日付、元タイトルの年へフォールバック。不明な場合は「年不明」。
- 14桁日時のファイル名をHH:MM:SSにする既存のタイトル表示を維持。ユーザー設定タイトルがあれば優先。
- 解像度・形式・時間、年の前後移動、サムネイル選択再生。
- 動画の10/35/65/90%地点から4コマの640×360プレビューを生成してキャッシュ。キャッシュキーはメディアIDとリソース情報・日付のハッシュ。
- 失敗した表紙は次のクロールで再試行。ツリー取得失敗時には、既存動画を削除・非表示にしない。
- 年・アルバム（フォルダ）や個々の動画の非表示（管理者のみ）。「非表示も表示」で一時的に表示して解除できます。
- タイトルの編集・リセット。HTML文字列の埋め込みではなくAPIデータをDOMのtextContentで描画。
- ブラウザでの再生、またはMediaRendererへSetAVTransportURI/Play/Pause/Stop。
- 「優先再生先」は希望であり、再生できない場合は自動で振り分けます（振り分けたときは画面下のトーストで通知し、再生中の場所をプレーヤーに表示）。
  - このブラウザ優先: ブラウザが再生できない形式（`canPlayType`で判定、または再生時のデコードエラー。例: MP4がない、HEVC）はDLNA機器へ送ります。送り先は優先再生先、最後に明示的に選んだ機器（ブラウザに記憶）、その他の順で、対応していないと分かっている機器は飛ばし、送信に失敗したら次の機器を試します。
  - DLNA機器優先: 機器のConnectionManager（GetProtocolInfoのSink一覧、MIMEとDLNA.ORG_PN）で対応を判定し（10分キャッシュ）、非対応・送信失敗・約20秒以内にPLAYINGにならない場合はこのブラウザで再生します。Sink一覧を取得できない機器は「不明」として送ってみます。
  - 連続再生（同じ年）: ブラウザでの再生中は次の動画ごとに同じ判定をし、DLNA機器で再生すべき動画に来たら残りのキューを機器へ引き継ぎます。DLNA機器でのキューはサーバー側で進み、非対応の動画や再生が始まらなかった動画はスキップ（件数を通知）し、全部再生できなければ停止します。
- 同一年内をアルバム・元タイトル順に連続再生し、既定ではループ。DLNAキューはサーバー側で管理し、ブラウザを閉じても継続。
- Pause/バッファリングを再生終了扱いにしない。PLAYINGを確認した後、STOPPEDと終端付近の再生位置で次に進む。

## データ

既定の保存先は `data/catalog.sqlite3` と `data/thumbs/`。`DLNA_DATA`で変更できます。
サムネイルは1本につき4フレームを並列に抽出します。同時に作るサムネイル数は `DLNA_THUMB_WORKERS`（既定4、クロールごと）、ffmpeg/ffprobeの同時プロセス数の上限は `DLNA_FFMPEG_JOBS`（既定16、全サーバー共通）で変更できます。
SQLiteには機器、元タイトル、追加タイトル、年、アルバム、日付、動画リソース（URL・形式・時間・解像度・サイズ）、DIDL-Lite、サムネイル状態を保存します。
追加タイトルはcustom_title列として分離されます。サーバーから消えた項目も行とタイトルを残し、完全なクロール成功時にavailable=0にします。
動画一覧はAPIから取得し、DBの最新情報で画面を構築します。動画情報を埋め込んだPHP/HTMLの事前生成はありません。

## LANから使う場合

環境変数 `DLNA_ADMIN_TOKEN` に自分で決めた長い管理者トークンを設定し、`--host 0.0.0.0`で起動します。
閲覧・再生だけを許可する家族向けには、別の値を `DLNA_GUEST_TOKEN` に設定します（任意）。
`DLNA_ADMIN_TOKEN` 未設定の場合、ループバック（127.0.0.1 / ::1）以外からの接続は403で拒否し、ループバックからの接続は管理者として扱います。LANから使うには管理者トークンが必須です。
旧名の `DLNA_TOKEN` も管理者トークンとして使えます。`DLNA_ADMIN_TOKEN` と異なる値が両方ある場合、管理者とゲストが同じ値の場合、管理者トークンなしでゲストトークンだけある場合は起動時にエラーになります。
ブラウザのログインフォームにはどちらのトークンでも入力でき、入力したトークンで役割が決まります（画面右上に「管理者」「ゲスト」と表示、「ログアウト」で切り替え）。

| 操作 | 管理者 | ゲスト |
| --- | --- | --- |
| 閲覧・ブラウザ再生・再生先（DLNA）の操作 | ○ | ○（非表示のものは除く） |
| 機器を検索・再クロール | ○ | ○ |
| 機器URLを指定して登録・取得元フォルダの指定 | ○ | × |
| タイトル編集 | ○ | × |
| 非表示にする／表示する・「非表示も表示」 | ○ | × |

非表示: 管理者は年・アルバムのカードの右上、動画カードのタイトル横の目のアイコンで非表示にできます。年を非表示にするとその年のアルバム・動画すべて、アルバムを非表示にするとその中の動画すべてが隠れます。
非表示の設定はクロールし直しても保持されます。「非表示も表示」にチェックすると非表示のものも薄く表示され（「非表示」バッジ付き）、アイコンから解除できます。
ゲストには非表示の年・アルバム・動画の一覧をAPIでも返さず、再生先（DLNA）キューへの追加も拒否します。
ただしこれは閲覧画面からの非表示であり、アクセス制御ではありません。ブラウザ再生はMediaServer（NAS）へ直接接続するため、動画URLを知っている人やNASへ直接アクセスできる人は再生できます。表紙画像（/thumbs）もURLを知っていれば取得できます（推測できないファイル名です）。
ブラウザで開くときのホスト名は `localhost` / `127.0.0.1` / `[::1]` だけが許可されます（DNSリバインディング対策）。
LANの別端末から開く場合は、そのURLに使うMacのIPアドレスやホスト名を `DLNA_ALLOWED_HOSTS` にカンマ区切りで指定します（例: `DLNA_ALLOWED_HOSTS=192.168.1.10,my-mac.local`、ポートは不要）。
接続元IPを絞る場合は `DLNA_ALLOWED_CLIENTS` にIP/CIDRをカンマ区切りで指定し、`!` を付けたものは除外します（例: `DLNA_ALLOWED_CLIENTS=192.168.1.0/24,!192.168.1.1`）。ループバックは常に許可され、トークンも引き続き必要です。
ルーターのLAN側アドレスを除外するのは、ポート転送・VPN・ヘアピンNATの通信がルーターのIPから来たように見え、外部からの接続がLAN内扱いになるのを防ぐためです。不正な指定があると起動時にエラーになります。

起動例（MacのmDNSホスト名が `mymac.local`、LANが `192.168.1.0/24`、ルーターが `192.168.1.1` の場合）:

```bash
DLNA_ADMIN_TOKEN="自分で決めた長い管理者トークン" \
DLNA_GUEST_TOKEN="別の長いゲストトークン" \
DLNA_ALLOWED_HOSTS="mymac.local" \
DLNA_ALLOWED_CLIENTS='192.168.1.0/24,!192.168.1.1' \
uv run uvicorn app.main:create_app --factory --host 0.0.0.0 --port 8765
```

LAN内の端末から http://mymac.local:8765 を開きます。`!` はbash/zshの履歴展開と衝突するため（ダブルクォート内でも展開されます）、`DLNA_ALLOWED_CLIENTS` の値はシングルクォートで囲んでください。

同じことを `launch.sh` で行えます（`-name` 省略時はMacのローカルホスト名、`-allowip` 省略時はLANサブネットを許可してルーターを除外、`-token`（管理者）省略時は環境変数、無ければ入力を求めます。`-guesttoken -` でゲストトークンの入力を求め、省略時は環境変数 `DLNA_GUEST_TOKEN` があれば使います）:

```bash
./launch.sh -name mymac -allowip '192.168.1.0/24,!192.168.1.1' -guesttoken -
```

手動で指定する場合、全インターフェース（`0.0.0.0`）ではなくLAN側IPだけで待ち受けるには、デフォルトルートのインターフェースからIPを取得して指定します:

```bash
LAN_IP=$(ipconfig getifaddr "$(route -n get default | awk '/interface:/{print $2}')") && echo "LAN IP: $LAN_IP" && \
DLNA_ADMIN_TOKEN="自分で決めた長い管理者トークン" \
DLNA_GUEST_TOKEN="別の長いゲストトークン" \
DLNA_ALLOWED_HOSTS="$LAN_IP,mymac.local" \
DLNA_ALLOWED_CLIENTS='192.168.1.0/24,!192.168.1.1' \
DLNA_INTERFACE="$LAN_IP" \
uv run uvicorn app.main:create_app --factory --host "$LAN_IP" --port 8765
```

この場合 `localhost` では開けないため、Mac自身からも http://mymac.local:8765 などで開きます（Mac自身の接続もLAN IPからの扱いになり、ログインが必要です）。
VPN接続中はデフォルトルートがVPN側になり、IPが取得できないか意図しないアドレスになることがあります。DHCPでIPが変わると再起動が必要なので、ルーターでIPを固定しておくと安心です。
ブラウザのログインフォームに管理者またはゲストのトークンを入力してください。これは家庭内LAN向けです。インターネットへ直接公開する構成ではありません。
SSDPの送信インターフェースを固定する場合は `DLNA_INTERFACE` にMacのLAN側IPv4アドレスを指定します。
`FFMPEG` / `FFPROBE`で実行ファイルのパスを指定できます。

## 常駐させる（LaunchAgent）

`install-daemon.sh` で `launch.sh` をLaunchAgentとして登録すると、ログイン時に自動起動し、異常終了時も再起動します。
ホスト名・許可する接続元・ポート・データの保存先・トークンを対話で聞き（Enterで既定値）、内容を確認してから登録します。
トークンは本人のみ読める設定ファイル（`~/Library/LaunchAgents/local.webvideo.plist`）に保存します。管理者トークンを空欄にすると自動生成して表示します。

```bash
./install-daemon.sh
```

オプション（`-name` / `-allowip` / `-port` / `-data`）で指定した項目は聞かれません。`-y` で質問せず既定値で登録します（管理者トークンは環境変数 `DLNA_ADMIN_TOKEN` で渡します）。

- データの保存先は既定で `~/Library/Application Support/webvideo`（`-data`で変更）。空なら `./data` をコピーして引き継ぎます。
- `./install-daemon.sh status` / `restart`（コード更新後）/ `logs` / `uninstall`。`-dry-run` で登録せずに設定を確認できます。
- 初回はローカルネットワークへのアクセス許可を求められることがあります。許可しないと機器検索やNASへの接続が失敗します。
- ログインしている間だけ動きます。画面なしで運用するMacでは自動ログインを有効にしてください。
- 手動で起動したサーバーが同じポートを使っていると登録できません。先に止めてください。
- 起動中にLAN IPが変わった場合は `restart` してください（ルーターでIPを固定しておくのがおすすめです）。

## 現時点の制約・実機確認事項

- NAS・テレビ実機との互換性は未検証。HTTP Range、M2TS/MTS、対応リソース、DIDLメタデータ、完了時の返り値は実機で確認が必要です。
- トランスコードはしません。レンダラーへはSink一覧で対応するリソースのうちM2TS/MTSを優先します。Sink一覧はコンテナ（MIME）とプロファイル名の照合のため、一覧上は対応でも実際のコーデックで再生できない場合は、再生が始まらないことで検出します（最初の1本は約20秒後にブラウザへ切り替え）。
- DLNA機器からブラウザへの途中での引き戻しはしません。機器でのキューはサーバーが進めるため、途中の動画が機器で再生できなければスキップします（ブラウザを閉じていても続くため）。ブラウザへ切り替わるのは、クリックした最初の動画が機器で再生できなかったときだけです。
- ブラウザで再生できるかはブラウザとOSのコーデック次第です（`canPlayType`は「maybe」を返すことが多く、HEVCなどは再生を始めてからのエラーで判定します）。video/quicktime（.mov）などMIMEで判定できない形式は、中身がH.264でもブラウザでは再生しない扱いになります。
- ブラウザ再生はMediaServerへ直接接続するため、クライアントからそのURLへ到達できる必要があります。
- クロール・キューの実行状態はメモリ上です。再起動後は操作で再開します。メタデータとタイトルと表紙は永続化されます。
- ObjectIDやUDNがサーバーDBの再構築で変わる場合、追加タイトルの自動付け替えは行いません。同名動画を誤って統合しないためです。
- 一部のサーバーは同じ動画を複数ビューで別ID公開します。refIDは統合しますが、refIDのない別IDの重複は残ります。
- 動画URL・サイズ・日付が変わらないまま内容だけ置換された場合、キャッシュを自動判定できません。
- SSDP結果には最終検出日時を保存しますが、オンラインを保証しません。再検索または操作結果で確認します。
- 再生位置やSTOPPEDを正しく返さない機器では、誤って次に進めないよう連続再生が止まる場合があります。短い動画の状態遷移も実機調整の対象です。
- 非表示はDLNAキューの開始時に確認します。再生中のキューに含まれる動画を後から非表示にしても、そのキューは止めません。
- 初期版はサーバー内の全動画一覧をブラウザへ取得します。数万件規模ではAPIページング・画面仮想化の追加を検討します。

## 検証

```bash
uv run pytest -q
```

XML（日本語・空白・複数リソース）、ページング、タイトル保持、キャッシュ更新、クロール失敗時の保持、API制御、ログイン、連続再生の状態遷移、再生先の自動振り分け（Sink一覧の解析とリソース選択、plan API、送信失敗のコード、非対応・再生が始まらない動画のスキップと全滅時の停止）、管理者/ゲストの権限、非表示（年・アルバム・動画の継承、クロール後の保持、既存DBの移行）を検証します。
`tests/demo.py`は実データと分離した合成動画で画面確認するためのfixtureです。MP4のない動画・MKVのみの動画と、TSしか受け付けない／形式不明でMKVを再生しない／オフラインの偽レンダラーを含みます（`DLNA_DEMO_DATA`に`sample.mp4`と、それを再多重化した`sample.m2ts`・`sample.mkv`を置きます）。

## 構成

- app/catalog.py: SQLite
- app/upnp.py: async-upnp-client経由の探索・Browse・SOAP操作
- app/jobs.py: クロール、FFmpegキャッシュ、再生キュー
- app/main.py: FastAPIとAPI
- app/static/: 動的な閲覧画面
